Once an interview's questions are generated, a session presents them to you one by one. After you submit each answer, a conversational AI interviewer responds with a brief 1–3 sentence follow-up, streamed in real time over Socket.io. The session tracks every answer and the time taken per question. When you finish, calling the complete endpoint triggers AI evaluation of each answer and generates your final report.

## Start a session

```http
POST /api/sessions/start
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "interviewId": "64f2b3c4d5e6f7a8b9c0d2e3"
}
```

The interview must have questions populated (i.e. `generationStatus: "generated"`). If an active session for this interview already exists for the current user, it is returned with `resumed: true` instead of creating a duplicate.

```json
{
  "success": true,
  "session": {
    "_id": "64f4d5e6f7a8b9c0d4e5f6a7",
    "userId": "64f1a2b3c4d5e6f7a8b9c000",
    "interviewId": "64f2b3c4d5e6f7a8b9c0d2e3",
    "status": "started",
    "answers": [],
    "startedAt": "2024-09-01T10:10:00.000Z"
  },
  "interview": {
    "_id": "64f2b3c4d5e6f7a8b9c0d2e3",
    "jobTitle": "Senior Backend Engineer",
    "questions": [ ]
  }
}
```

## Submit an answer

```http
POST /api/sessions/:id/answer
Authorization: Bearer <token>
Content-Type: application/json
```

<ParamField body="questionId" type="string" required>
  The `_id` of the question subdocument from the interview. Must belong to the linked interview.
</ParamField>

<ParamField body="answerText" type="string">
  The candidate's typed answer for this question. If omitted, defaults to an empty string.
</ParamField>

<ParamField body="timeTaken" type="number">
  Time in seconds the candidate spent on this question. Stored for reporting.
</ParamField>

<ParamField body="skipped" type="boolean">
  Set to `true` if the candidate skipped this question. Skipped answers receive `aiScore: 0` and the feedback `"Question was skipped."` during final evaluation.
</ParamField>

```json
{
  "questionId": "64f3c4d5e6f7a8b9c0d3e4f5",
  "answerText": "I implemented a write-through cache using Redis with a TTL of 300 seconds. The main trade-off was accepting slightly stale reads in exchange for much lower database load. I used cache invalidation on write to handle consistency for critical paths.",
  "timeTaken": 95,
  "skipped": false
}
```

Submitting a second answer for the same `questionId` within the same session overwrites the previous answer rather than creating a duplicate entry.

## Real-time AI follow-up via Socket.io

Hiretrack streams a conversational interviewer response for each answer using Socket.io. The server connects Socket.io to the same HTTP server as the REST API and uses CORS credentials, scoped to the `CLIENT_URL` origin.

### Connection

```javascript
import { io } from "socket.io-client";

const socket = io("https://your-hiretrack-api.com", {
  withCredentials: true,
});

socket.on("connect", () => {
  console.log("Connected to Hiretrack live interview socket:", socket.id);
});
```

### Emitting an answer

After displaying a question, emit a `live_answer` event with the question text, the candidate's answer, and the question's expected keywords:

```javascript
socket.emit("live_answer", {
  questionText: "Describe how you implemented a caching strategy to reduce database load.",
  answerText: "I used Redis with a write-through strategy and a 5-minute TTL...",
  expectedKeywords: ["cache invalidation", "TTL", "Redis", "eviction policy"],
});
```

### Receiving the streamed response

```javascript
let aiResponse = "";

// Each token chunk arrives here as the model streams
socket.on("ai_chunk", (chunk) => {
  aiResponse += chunk;
  // Append to your UI in real time
  document.getElementById("ai-response").textContent = aiResponse;
});

// Stream is complete — AI has finished speaking
socket.on("ai_complete", () => {
  console.log("AI interviewer finished:", aiResponse);
  // Enable the "Next Question" button
});

// Something went wrong server-side
socket.on("ai_error", (message) => {
  console.error("AI error:", message);
  // Show fallback UI
});

// Clean up on component unmount
socket.on("disconnect", () => {
  console.log("Disconnected from live interview socket");
});
```

### Socket.io event reference

| Event | Direction | Payload | Description |
|-------|-----------|---------|-------------|
| `live_answer` | Client → Server | `{ questionText, answerText, expectedKeywords }` | Send the candidate's answer for AI follow-up |
| `ai_chunk` | Server → Client | `string` | One streamed text token from the model |
| `ai_complete` | Server → Client | _(none)_ | Signals the AI has finished its response |
| `ai_error` | Server → Client | `string` | Error message if the Groq call fails |

### How the AI interviewer works

When the server receives a `live_answer` event, it builds a prompt instructing Groq to act as a conversational interviewer and produce a **1–3 sentence** follow-up based only on what the candidate said. The model (`llama-3.3-70b-versatile`, `temperature: 0.5`, `max_tokens: 150`) streams back tokens one by one, and each token is emitted as an `ai_chunk` event to the same socket. A final `ai_complete` event is emitted after the stream loop finishes.

The AI does not evaluate or score the answer at this stage — that happens when you call the complete endpoint. The real-time follow-up is conversational only: an acknowledgment, a clarifying probe, or a brief commentary grounded in the candidate's answer.

## Complete a session

```http
POST /api/sessions/:id/complete
Authorization: Bearer <token>
```

Ending a session triggers two AI operations:

1. **Per-answer evaluation** — each non-skipped answer is scored 1–10 by Groq with constructive feedback. Skipped answers automatically receive `aiScore: 0`.
2. **Overall report generation** — `generateOverallFeedback` produces an `overallScore` (1–100), `strengths`, `weaknesses`, and `improvementTips` arrays.

The session `status` is set to `"completed"`, `completedAt` is stamped, and the linked interview status is updated to `"completed"`. The user's `totalSessions` counter is incremented.

```json
{
  "success": true,
  "session": {
    "_id": "64f4d5e6f7a8b9c0d4e5f6a7",
    "status": "completed",
    "completedAt": "2024-09-01T10:45:00.000Z",
    "overallScore": 74,
    "strengths": ["Strong Redis caching knowledge", "Clear explanation of trade-offs"],
    "areasForImprovement": ["Lacked depth on distributed locking", "No mention of monitoring cache hit rates"],
    "answers": [
      {
        "questionId": "64f3c4d5e6f7a8b9c0d3e4f5",
        "questionText": "Describe your Redis caching strategy...",
        "answerText": "I used Redis with a write-through strategy...",
        "aiScore": 8,
        "aiFeedback": "Strong answer covering TTL and write-through patterns. Consider also addressing cache stampede prevention.",
        "timeTaken": 95,
        "skipped": false
      }
    ]
  }
}
```

<Warning>
  The Socket.io layer does not independently authenticate the socket connection beyond checking the CORS origin. Do not expose the socket server to untrusted origins. Always set `CLIENT_URL` to your exact frontend domain in production and avoid wildcard CORS configurations on the socket server.
</Warning>
